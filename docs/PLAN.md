# Anemone port plan

Anemone is a Swift/tvOS port of [Wholphin](https://github.com/damontecres/Wholphin) (Android TV, Kotlin + Compose, ~92k lines). The parity baseline is Wholphin commit `5f2f9a8` (2026-10-28), moved up from `52c26bc` (2026-10-25) and then `cecfdae` (2026-10-26) once the commits between them were ported or skipped; see "Tracking upstream" at the end.

## Decisions

| Topic | Decision |
|---|---|
| License | GPL-3.0. Wholphin is GPL-2.0-or-later, so its logic can be ported directly. Distributed through the App Store without a separate grant from the Wholphin author; see "GPL and the App Store" below. |
| Repo | This repo, a fresh history. Wholphin is a reference, not a git remote. |
| Distribution | App Store is the goal; TestFlight along the way. |
| Platforms | tvOS 26+ now (runs on every Apple TV, including HD and 4K 1st gen). iOS/iPadOS later (Phase 7). |
| Server | Jellyfin 12.0+ only. Jellyfin 12 removed `GET /QuickConnect/Initiate`, legacy route prefixes, and legacy auth by default. Wholphin is already warning users on older servers. |
| Bundle ID | `com.revanthv11.anemone`, shared later by the iOS app for universal purchase. Confirm before registering in App Store Connect. |
| Seerr | Not in 1.0. Release builds leave `ANEMONE_SEERR` unset (Phase 5d), so nothing of Seerr is built; it waits for a later release. |

### GPL and the App Store

The FSF considers Apple's App Store terms incompatible with the GPL; in practice it only matters if a copyright holder complains (VLC 2011, GNU Go 2010). To lower the risk:

- Use a custom EULA in App Store Connect that points to the GPL, not Apple's standard EULA.
- Tag the source for every TestFlight and App Store build, so each shipped build has public matching source.
- Keep an in-app licenses screen that credits Wholphin.

## tvOS constraints that shape the design

- **Storage can be purged.** Only a small amount of UserDefaults is guaranteed to persist; everything else can be purged when space runs low.
  - Servers and tokens go in the Keychain.
  - A local database is a cache only.
  - Anything that matters syncs to the server through DisplayPreferences `customPrefs`, as Wholphin already does for `home_settings` and `removeNextUp`.
- **Server discovery.** Jellyfin discovery is a UDP broadcast on port 7359. That needs Apple's multicast entitlement, which requires approval, and tvOS support is unclear. Manual URL and Quick Connect come first.
- **Siri Remote.** There are no key-repeat counts. Wholphin's left/right seek with hold acceleration needs press-began/ended timers, plus clickpad swipe scrubbing.
- **SwiftUI focus.** Focus restoration and performance in nested lazy rows is the biggest UI risk; it's the first spike.
- **Players.**
  - AVPlayer gives Dolby Vision (MP4 / fMP4 HLS only), Atmos via EAC3-JOC, AirPlay and frame-rate matching. It can't play MKV, DTS, TrueHD, ASS or PGS.
  - MPV direct-plays almost anything, with libass for ASS. It can't output Dolby Vision; frame-rate matching must be set manually.
  - Neither can bitstream TrueHD or DTS.
  - Mirrors Wholphin's `PREFER_MPV` rule, which sends HDR to the native player.
- **Device profile.** There's no `MediaCodecList`. Use one static profile per engine plus runtime checks (`VTIsHardwareDecodeSupported`, AVPlayer HDR eligibility).
- **No system screensaver API.** The screensaver is in-app only.
- **Per-user UI language** isn't practical on tvOS (the app language is a system setting). Dropped.

## Architecture

- **`App/`:** the tvOS app target. Composition root, navigation, and tvOS screens.
- **`TopShelf/`:** the Top Shelf extension. Reads the app's sign-ins through a shared Keychain access group, and its Next Up settings through an App Group.
- **`Packages/AnemoneKit`:** one local package, five libraries:
  - **AnemoneCore:** models, `Destination`, `HomeRowConfig` Codable types, stream-choice scoring, device profiles, settings. Pure Swift; tests run on macOS.
  - **AnemoneJellyfin:** session, repositories, WebSocket, playback progress reporting.
  - **AnemonePlayback:** a `PlayerEngine` protocol with AVPlayer and MPV engines, the playback state machine, segment / next-up / pass-out logic, trickplay. One custom SwiftUI overlay shared by both engines (MPV can't use `AVPlayerViewController`).
  - **AnemoneSeerr:** the generated Seerr client, behind a build flag.
  - **AnemoneUI:** design tokens, cards, rows, grids, backdrop, context menu.
- The packages stay platform-neutral; tvOS-only code goes behind `#if os(tvOS)`. Screens are per platform, because tvOS is built around focus and iOS around touch.

### Compatibility with Wholphin

- Use the same home-row JSON schema (v1).
- Support [jellyfin-plugin-wholphin](https://github.com/damontecres/jellyfin-plugin-wholphin) (`GET /wholphin/public`, `GET /wholphin/homesettings`, and in builds with Seerr `GET /wholphin/seerrsettings`), so admins configure home layouts, and Seerr's address and login, once for both apps.
- Offer "Import from Wholphin" by reading its DisplayPreferences entry (id `default`, client `Wholphin`, key `home_settings`). Anemone writes its own entry under client `Anemone`.

### Seams

So the rest of the plan can be built in separate files, side by side:

- **Player engine:** `PlaybackController` drives a `PlayerEngine`, never AVPlayer itself. An engine loads a URL at a start position, plays, pauses, seeks exactly, reports the time, duration and rate, sends status, end and failure events, lists and selects audio and subtitle tracks, and gives the UI its video output. `AVPlayerEngine` and `MPVPlayerEngine` (Phase 4) both conform, as Swiftfin's AVPlayer and MPV players do, and, with Prefer MPV, `SwitchingEngine` picks one for each entry.
- **Queue:** the controller plays a `PlaybackQueue` of entries (item, start position, metadata). Pages ask for playback with a `PlaybackRequest` (a queue, whether to shuffle, and what follows) from the builders in `App/Playback/PlaybackSupport.swift`, and `.player($request)` builds the controller. `play(entryAt:)` and `playNext()` play another entry with its own PlaybackInfo and play session, after ending the current session.
- **Playback features:** each `PlaybackFeature` hears the controller's events in order (loaded, started, position once a second, paused, resumed, ended, failed, stopped), acts through the controller, and shows controls through `PlayerAccessories`: actions, transport-bar menus and a card. The system player shows them as `contextualActions`, `transportBarCustomMenuItems` and a card over the video; Anemone's overlay (3e) shows the same. Features are listed in `PlaybackController.features(for:)`; the first is `ProgressReporting`. At the end of an entry the player closes, unless a feature played another entry or set `closesAtEnd` to `false`; `finish()` closes it. Before each PlaybackInfo request the controller lets every feature `prepare(_:)` the `StreamRequest` (version, device profile, audio and subtitle indices), so a feature such as `TrackSelection` asks for its tracks without the controller knowing about it. `reload()` asks for the current entry again (for a track the stream doesn't carry) and plays on from the same position: features hear `stopped`, then `reloaded` instead of `loaded`, so what they keep for an entry, such as skipped segments or a cancelled Up Next, carries on.
- **Settings:** `App/Settings/SettingsView.swift` has the account (switch user, profile lock, sign out) and a page each for Sidebar, Home, Playback, Subtitles, Interface, Appearance, Screensaver and About, and for Seerr in builds with it. Playback links to a page per part of playback. A setting is a `Preference` (a UserDefaults key and a default, with Wholphin's name and default where it has one), declared in an extension of `Preferences` next to what uses it, read with `value()` and bound with `@AppStorage(Preferences.someSetting)`.
- **Library kinds:** Live TV, music and photo libraries open `App/LiveTV`, `App/Music` and `App/Photos`.
- **UI tests:** `UITests/Support` has helpers to launch, wait for Home, press sequences, move and wait for focus, open a sidebar destination and attach screenshots. `UITests/SmokeUITests.swift` plays an item from Continue Watching for about 10 s, and runs only when asked to; its doc comment has the command.

Apart from Settings, now a list with a page for each part of the app, nothing visible changed. Tested live in the simulator against the Jellyfin 12.3 demo server: resuming a movie by direct play and closing with Menu still updates Resume on its page; Settings opens each page and comes back; the music library still shows its grid. With a throwaway feature, the system player showed a card over the video with focus on its first button, a contextual action, and a menu above the transport bar whose choice showed as selected. Not verified live: the Live TV and photo pages (the demo server has neither kind of library), listing and choosing tracks through the engine, and moving through a queue of more than one entry, which only the unit tests covered then. Later phases checked them live: the Live TV and photo pages in 5a and 5c, tracks in 3d and queues in 3b.

- [x] Server discovery in AnemoneJellyfin: `ServerDiscovery` sends Jellyfin's "who is JellyfinServer?" to UDP port 7359 at each network's broadcast address and 255.255.255.255, then for 5 s lists each server that answers, once, from its JSON reply (id, name and address). Tested live against the Jellyfin 12.3 demo server (adding the server, the profile list, getting a Quick Connect code) and against the maintainer's own Jellyfin 12.2 server: password sign-in, session restore, PIN lock and unlock, a locked profile not being restored on launch, and sign-out.

tvOS ignores `.keyboardType(.numberPad)`, so PIN entry uses the full on-screen keyboard. A custom PIN pad is an idea for later.

Server discovery is tested only by unit tests on macOS, against a stand-in server on 127.0.0.1 at a port the system picks: the probe's text, a reply becoming a server, a server answering twice listed once, stray datagrams ignored, a nameless server going by its host, the search ending on time, stopping early closing its socket, and which interfaces' broadcast addresses are used. Not verified live: a real Jellyfin server answering a broadcast, and anything on Apple TV. Nothing in the app calls it yet.

Not yet: the multicast entitlement (`com.apple.developer.networking.multicast`), which iOS needs to send a broadcast and tvOS may too (the multicast spike checks on hardware). It's a user and Apple step: the maintainer asks Apple for it (developer.apple.com/contact/request/networking-multicast), then it goes in the app's entitlements and provisioning profile. After that, a "found nearby" list on the add-server screen, each server added through `ServerConnector` like a typed address, as Wholphin's server list does.

##### Using the theme

For anyone theming a view. Read the theme with `@Environment(\.theme) private var theme`. Its roles are shape styles, so they go straight into `.foregroundStyle(theme.secondaryText)`, `.fill(theme.progress)` or `.background(theme.cardBadge, in: .capsule)`; where an API wants a `Color` (`shadow(color:)`, `LinearGradient(colors:)`), use `.color`, as in `theme.scrim.color.opacity(0.6)`.

- **A view hosted on its own shows purple unless its root has `.appTheme()`.** Without it, `\.theme` is `Theme.standard`, purple, whatever the user chose, and nothing warns you. A `UIHostingController`'s root doesn't inherit the app's environment: the player overlay's (`OverlayHost` in `AnemonePlayer.swift`) and the screensaver's (`ScreensaverView`) have `.appTheme()`; give it to any new one. Use `.appTheme()` there, not `themeBackground()`, which would cover the video. SwiftUI's own sheets and full-screen covers inherit it.
- **Anemone is dark-only, as Wholphin is on TV.** `appTheme()` keeps the app in dark mode whatever the Apple TV's appearance setting. Don't design a view for light mode; the light palettes are there for the iOS app.
- **The theme doesn't tint system controls.** `appTheme()` leaves `.tint` alone, so tvOS's glass buttons, toggles and list rows keep their own focus look (bold blue's accent on a focused glass button was 1.5 to 1). Colour Anemone's own components with the roles below. Views that mark something with `.tint` (Music's playing track, Now Playing's toggles, the music library's and Live TV's markers, the jump bar's letter) get the system's tint, not the theme's: give them `accent` or `highlight`.
- **`withAlpha(_:)`, not `opacity(_:)`, to set a role's alpha.** `theme.focusRing.withAlpha(0.5)` replaces the alpha, as Compose's `copy(alpha =)` does. SwiftUI's `opacity(_:)`, on a role or its `.color`, multiplies the alpha it already has, as for any colour: purple's `focusRing` is 75%, so `.opacity(0.5)` draws it at 37.5%. `over(_:)` gives what a colour looks like drawn over another, for checking contrast.

| Role | For | Instead of |
|---|---|---|
| `background` | Behind a page. The root already draws it; a view only needs it when it covers the root, like a full-screen cover | `Color.black` behind pages |
| `onBackground`, `secondaryText` | Titles and text on the page; captions, metadata and row subtitles | `.white`, `.primary` and `.secondary` text on the page |
| `scrim` | Gradients and dimming over artwork: `theme.scrim.color.opacity(0.6)` | `.black.opacity(…)` over artwork |
| `surface`, `onSurface` | Opaque panels, sheets and dialogs on the page | `.black.opacity(…)` panels |
| `surfaceVariant`, `onSurfaceVariant` | Placeholders for missing artwork, quiet chips | `.quaternary` fills, `.tertiary` symbols |
| `accent` | What's selected or current in Anemone's own components: a tab's underline, a chosen option's mark. Not the app's tint | `.white` underlines and markers, `.tint` marks |
| `highlight` | Text that marks the current choice where `accent` is too dark to read, like a jump bar's current letter | `.tint` on text |
| `primary`, `onPrimary` | Filled buttons and their labels | |
| `focusRing`, `focusGlow` | A ring around a focused card or tile, `Theme.focusRingWidth` wide, and a glow under something that draws its own lift | White focus borders, black focus shadows, other widths |
| `platter`, `onPlatter`; `focusedPlatter`, `onFocusedPlatter` | Custom focusable controls at rest and focused, as Wholphin's buttons: a quiet fill with light text, then light with dark text | `isFocused ? .white : .white.opacity(…)` and `isFocused ? .black : .white` |
| `cardBadge`, `onCardBadge` | Counts and small labels over artwork | `.black.opacity(0.6)` with `.white` text |
| `watchedBadge`, `onWatchedBadge`, `favorite` | The watched check and the favourite heart | `.white` checks, `.red` hearts |
| `progress`, `progressTrack` | How much has been watched, on cards and pages | `.white` on `.black.opacity(0.5)` |
| `seekPlayed`, `seekBuffered`, `seekTrack` | The player's seek bar | `.white`, `.white.opacity(0.25)` |
| `error`, `onError`, `errorContainer`, `onErrorContainer` | Error text on the page, and filled error banners | `.red`, `.orange` |

Don't hard-code a colour a theme should change: no `.white`, `.black`, `.red`, `.blue` or hex values for chrome. If no role fits, add one to `Theme` with where Wholphin takes it from, rather than reaching into `theme.palette` in many places. Keep as they are:

- the system's controls and focus effects (glass buttons, toggles, `.hoverEffect(.highlight)`, the default button and list styles, parallax), untinted: the theme only colours Anemone's own components. Inside a system list row or button that turns white when focused, leave text to the system's `.primary` and `.secondary`, which adapt; a fixed `secondaryText` there would be light grey on white;
- system materials (`.regularMaterial`, glass) that blur what's behind them, such as the player's panels;
- black behind video and photos, which is letterboxing, not chrome; the user's subtitle colours; artwork; Live TV's programme category colours, which Wholphin fixes too.

To check a view in another theme without the Settings page, launch with `-appThemeColors oledBlack` (or `purple`, `blue`, `green`, `orange`, `boldBlue`, `red`, `brown`).

A view that marks its own focus or selection, like a list row or a list's style of button, colours its label with `onFocusedPlatter` when focused and `onBackground` otherwise, and its quieter text with `.secondary`, which follows that foreground.

##### VoiceOver

- **Cards read themselves.** `MediaCard` and `PersonCard` are one element each, labelled from their title, subtitle and marks. Don't put `.accessibilityLabel(title)` on a card's button: it would replace the marks. Pass `spokenSubtitle: item.spokenSubtitle` where the subtitle is an episode's "S1:E3".
- **Rows are groups named by their titles**: `.accessibilityElement(children: .contain)` and `.accessibilityLabel(Text(verbatim: title))` on the row, and `.accessibilityHidden(true)` on the title it shows, so the title is read once, as focus moves into the row, as `HomeRowView` does. A title that doesn't name a group is a heading (`.isHeader`).
- **Pictures are decoration** unless they're the only name of something: `ShapedArtwork`, `BackdropImage` and a card's artwork are hidden already, and `LogoImage` reads its title. A symbol that only marks a choice (a check) is hidden, and the row gets `.isSelected`; an icon-only button gets a label.
- **Build spoken labels from parts**, each a whole string a translator can reorder: `.accessibilityLabel { _ in Text(verbatim: title); Text("\(count) unwatched") }`, which VoiceOver reads with pauses between, not `title + ", " + …`. Names from the server are `Text(verbatim:)`; words of the app's own are literals.
- `focusedElement(in:)` in a UI test returns the focused button, whose `label` is what VoiceOver reads.

##### Words and the String Catalogs

- **Words are found by the compiler.** A literal Xcode can see as a `LocalizedStringKey` (`Text("…")`, `Button("…")`), a `LocalizedStringResource` or a `String(localized:)` goes into the target's catalog when it builds; a `String` literal doesn't, and always shows English. Where a value stays a `String` (a row's title, an error message), write `String(localized: "…")`; in a package, add `bundle: .module`, or the lookup goes to the app's catalog. AnemoneUI's `LocalizedStringResource`s use `bundle: .anemoneUI`.
- **Whole sentences, one key each.** Put names in with interpolation (`"Couldn't load \(name)."`), never `"Couldn't " + what` or a noun dropped into a sentence; a translator may need to move them. Counts are one key with plural forms in the catalog (`"\(count) items"`), not `count == 1 ? "1 item" : …`. Interpolate a `Double` formatted (`\(rating, format: …)`): a bare one prints six decimals.
- **Catalogs.** Building in Xcode adds new strings to the catalogs. From the command line, `xcodebuild` only writes `.stringsdata`; `xcrun xcstringstool sync <catalog> --stringsdata <files>` merges them. Build with Seerr on too, or its views' strings go stale. Then rerun `scripts/import-wholphin-strings.py` with a Wholphin checkout to pick up its translations for the new strings.
